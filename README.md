# Library Loan API

RREST API untuk mengelola data peminjaman buku oleh anggota perpustakaan. Proyek ini dikembangkan menggunakan Node.js dan Express.js dengan Supabase sebagai database. API menyediakan operasi CRUD (Create, Read, Update, Delete) serta fitur filter data berdasarkan status peminjaman.

Proyek ini dibuat untuk menerapkan konsep REST API, pengelolaan database, pengujian endpoint menggunakan Postman, dan deployment aplikasi backend agar dapat diakses secara publik melalui Vercel serta untuk memenuhi responsi praktikum ppb modul 1.

## Struktur data

API menggunakan tabel `loans` di Supabase dengan kolom berikut:

| Kolom | Tipe yang disarankan | Keterangan |
| --- | --- | --- |
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` | ID unik positif |
| `borrower_name` | `TEXT NOT NULL` | Nama peminjam |
| `book_title` | `TEXT NOT NULL` | Judul buku |
| `loan_date` | `DATE NOT NULL` | Tanggal peminjaman |
| `due_date` | `DATE NOT NULL` | Batas tanggal pengembalian |
| `return_date` | `DATE` | Tanggal buku dikembalikan; boleh `NULL` |
| `status` | `TEXT NOT NULL` | Status peminjaman |

Nilai `status` yang diterima API: `Dipinjam`, `Dikembalikan`, atau `Terlambat`. Kolom `id` harus berupa angka positif. Jika tabel belum dibuat, contoh SQL berikut dapat digunakan di Supabase SQL Editor:

```sql
CREATE TABLE public.loans (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    borrower_name TEXT NOT NULL,
    book_title TEXT NOT NULL,
    loan_date DATE NOT NULL,
    due_date DATE NOT NULL,
    return_date DATE,
    status TEXT NOT NULL DEFAULT 'Dipinjam'
        CHECK (status IN ('Dipinjam', 'Dikembalikan', 'Terlambat'))
);
```

Pastikan kebijakan Row Level Security (RLS) Supabase mengizinkan operasi yang dibutuhkan API. Simpan `SUPABASE_KEY` di environment server, jangan gunakan atau publikasikan service role key di aplikasi klien.

## Instalasi dan menjalankan lokal

Persyaratan: Node.js dan proyek Supabase dengan tabel `loans`.

1. Clone repository dan masuk ke folder proyek.
2. Pasang dependency:

   ```bash
   npm install
   ```

3. Buat file `.env` di root proyek:

   ```env
   SUPABASE_URL=https://<project-id>.supabase.co
   SUPABASE_KEY=<supabase-api-key>
   PORT=3000
   ```

   Gunakan API key Supabase yang sesuai dengan konfigurasi RLS. Jangan commit file `.env`.

4. Jalankan server:

   ```bash
   npm start
   ```

Server lokal berjalan di `http://localhost:3000`. Endpoint root `GET /` menampilkan informasi API, sedangkan endpoint peminjaman tersedia di `http://localhost:3000/api/loans`.

## Endpoint API

Semua endpoint peminjaman menggunakan prefix `/api/loans`. Request dengan body harus menggunakan `Content-Type: application/json`.

| Method | Endpoint | Keterangan |
| --- | --- | --- |
| `GET` | `/api/loans` | Mendapatkan semua peminjaman |
| `GET` | `/api/loans?status=Dipinjam` | Filter peminjaman berdasarkan status |
| `GET` | `/api/loans/:id` | Mendapatkan satu peminjaman |
| `POST` | `/api/loans` | Membuat peminjaman |
| `PUT` | `/api/loans/:id` | Memperbarui satu atau lebih kolom |
| `DELETE` | `/api/loans/:id` | Menghapus peminjaman |

### Contoh request dan response

**Membuat peminjaman**

```http
POST /api/loans
Content-Type: application/json
```

```json
{
    "borrower_name": "Amira",
    "book_title": "PPB",
    "loan_date": "2026-10-13",
    "due_date": "2026-10-20"
}
```

`status` otomatis bernilai `Dipinjam`

```json
{
    "message": "Data peminjaman berhasil ditambahkan",
    "data": {
        "id": 6,
        "borrower_name": "Amira",
        "book_title": "PPB",
        "loan_date": "2026-10-13",
        "due_date": "2026-10-20",
        "return_date": null,
        "status": "Dipinjam",
        "created_at": "2026-10-09T18:15:46.578477+00:00"
    }
}
```

**Mendapatkan data**

`GET /api/loans?status=Dipinjam` menghasilkan array data:

```json
[
    {
        "id": 3,
        "borrower_name": "Citra",
        "book_title": "Struktur Data",
        "loan_date": "2026-10-09",
        "due_date": "2026-10-16",
        "return_date": null,
        "status": "Dipinjam",
        "created_at": "2026-10-09T17:11:54.894215+00:00"
    }
]
```
`return_date` bernilai `null` karena tidak dikirim dan memang belum waktunya untuk dikembalikan, namun nantinya bisa kita edit dengan PUT kemudian diisi body raw nya untuk status telah dikembalikan.

**Memperbarui peminjaman**

`PUT /api/loans/6` dengan body:

```json
{
  "return_date": "2026-10-20",
  "status": "Dikembalikan"
}
```

Response sukses berisi pesan dan record yang diperbarui:

```json
{
    "message": "Data peminjaman berhasil diperbarui",
    "data": {
        "id": 6,
        "borrower_name": "Amira",
        "book_title": "PPB",
        "loan_date": "2026-10-13",
        "due_date": "2026-10-20",
        "return_date": "2026-10-20",
        "status": "Dikembalikan",
        "created_at": "2026-10-09T18:15:46.578477+00:00"
    }
}
```

`DELETE /api/loans/[id]` menghapus record dan mengembalikan objek `message` serta `data` yang dihapus. ID tidak valid, status tidak didukung, atau input wajib yang tidak valid akan menghasilkan response error JSON; ID yang tidak ditemukan menghasilkan status `404`.
contoh response `DELETE /api/loans/7`:
```json
{
    "message": "Data peminjaman berhasil dihapus",
    "data": {
        "id": 7,
        "borrower_name": "Alvin",
        "book_title": "PPB",
        "loan_date": "2026-10-13",
        "due_date": "2026-10-20",
        "return_date": null,
        "status": "Dipinjam",
        "created_at": "2026-10-09T18:16:29.243898+00:00"
    }
}
```
